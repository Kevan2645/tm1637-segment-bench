User guide

Segment Bench

A browser-based simulator for a TM1637-style 4-digit 7-segment display. Design and preview text/number message sequences with LONG / MEDIUM / SHORT timing tiers and ~150 ms refresh quantization — without flashing any hardware.

No install · no account · nothing leaves your browser

01 · Layout

The display & transport

The hero panel at the top of the page is a live render of a 4-digit display, driven by whatever step is currently playing.

The transport row underneath it controls playback, not content:

ControlDoes
⟲ RestartJumps to the first enabled step and resets its timer.
Play / PauseToggles autoplay. While paused, the display holds on the current step indefinitely.
Step ▸Advances to the next enabled step by hand — works whether or not autoplay is running.
Brightness (0–7)Fades the lit-segment glow in the preview only. It isn't part of a saved or exported file.

The step counter on the right (Step 3 / 11) always reflects the step actually on screen, whether it got there by autoplay, a manual Step ▸, or you clicking directly into a field in the editor below — editing a step always jumps the display to it, so you're never typing into a step you can't see.

02 · Reference

The alphabet

A 7-segment digit can't draw every letter the way you'd write it by hand — the reference grid on the right side of the workbench shows exactly what each character becomes.

Loading…

Two dot colors in the grid's legend mark how confident each glyph is:

  • Common convention — matches what most TM1637-style firmware and fonts actually render for that character.
  • Playground — a plausible approximation included for completeness, but less standardized; it may look different on your specific display.

Case matters here in a way it doesn't on paper

Seven letters — R N D T B Q Y — only have one shape a 7-segment digit can physically draw. What most fonts call the "lowercase" form is the only renderable form, so typing the natural, all-caps spelling of a word still lights the same segments as its lowercase counterpart. Typing END reads on screen as End; OVR reads as Ovr. That's correct — it's what those letters actually look like lit up — not a typo in the tool.

I and i are the deliberate exception in the other direction: the bench draws them as two visibly different glyphs (a two-segment bar vs. a single stroke) so a word using both cases stays legible, even though real firmware usually sends the same single segment for both.

03 · Editor

Building a message

A message is an ordered list of steps. The display plays them in order, looping back to the first enabled step after the last.

Step types

  • Text — up to 4 characters, using the alphabet above. Longer input is truncated; unsupported characters show a warning right on the row.
  • Number — any integer. Only the last 4 digits show, right-aligned, using true numeral segments (not the letter alphabet).
  • Blank / pause — shorthand for an empty text step, typically on the SHORT tier, used as a gap between two words.

Each row in the list

1 Text HELP MEDIUM ↑ ↓ ✕

From left to right: the step's position, an include-in-playback checkbox, the step's fields (kind, content, timing tier), and controls to reorder or delete it.

Unchecking a step's box removes it from playback immediately — if it was the step currently on screen, the display jumps off it right away rather than waiting out its duration — but the row stays in the list, and stays in anything you save or export. It's a way to shelve a step temporarily without losing it.

Live preview while you type. Clicking into any field — the text box, the number, a tier — jumps the hero display straight to that step and holds it there. Autoplay won't cycle it away mid-edit; it resumes its normal timing once you move on.

04 · Persistence

Saving & loading your work

Nothing here saves itself. Every edit is exploratory — a "let me just see what this looks like" — until you deliberately save it.

💾 Save data file

Downloads a plain .json file containing exactly three things: your timing tiers, the brightness setting, and the full step list. Nothing else — no copy of this page, no code.

The filename is suggested automatically from your message (see naming, below), shown live as as help-repeat-safe.json next to the button. If your browser is set to ask where to save, it'll flag it if that name already exists so you can bump it, e.g. to -2.

📂 Load data file

Reopens a file saved this way (or one produced by Export config) right here on this page. Open two files back to back to compare two sequences.

Why this stays two pieces, not one. A data file carries no copy of the bench's own display logic — only the sequence data. That means every fix ever made to this page (a corrected glyph, a display bug fix) applies retroactively to every sequence you've ever saved, the next time you open it, with nothing to re-save. An earlier version of this tool baked the whole page into every saved file; that made each save a permanent fork, immune to later fixes. This version deliberately doesn't.

05 · Timing

Timing tiers

Rather than setting a duration on every single step, most steps just reference one of three shared tiers — change the tier once, and every step using it updates together.

TierTypical useRange
LONGThe main content of a message — a word or number meant to actually be read.50–1200 ms
MEDIUMSecondary or repeated words, status labels.50–1200 ms
SHORTBlanks and quick pulses between words.20–1200 ms

Any individual step can override its tier with custom and its own millisecond value, for the rare step that needs a duration none of the three tiers should be bent to fit.

Why "actual" differs from what you typed

The simulator polls for a step change every ~150 ms — deliberately matching the real firmware's own refresh loop, rather than timing steps to the exact millisecond. A duration doesn't end the instant it's reached; it ends at the next poll after that point. Each tier's row shows both numbers side by side, e.g.

target 450ms → ~450ms actual on screen

A target that doesn't land on a clean multiple of 150 rounds up to the next poll — e.g. a target of 460ms would show ~600ms actual. Real hardware adds its own timing jitter on top of this, which the simulator doesn't model.

06 · Handoff

Export config

For handing a finished sequence to whoever's wiring it into actual firmware — a teammate, a repo, or a chat where you'd rather not describe the steps in words.

⤓ Export config opens a read-only text box with the sequence as JSON: tiers and the full steps array, including any disabled steps (so nothing is silently dropped — it's left to whoever reads the export to decide what to do with them). brightness and playback position are deliberately left out, since neither has a real-firmware equivalent.

Copy it straight into a chat, or use Download .json to save it as a file.

This is not the same button as Save data file — export is for handing off to firmware; save/load is for keeping working on the sequence in this tool. Either file can be reopened here with Load data file, since both share the same core shape.

07 · Fine print

Notes & gotchas

  • Nothing autosaves — including across reloads. Refreshing the page resets to the built-in example sequence. Save before you navigate away from anything you want to keep.
  • Text steps truncate at 4 characters and flag any character with no glyph in the alphabet reference, right on the step's row.
  • Suggested filenames are a convention, not a lock. Each word gets a short code plus a one-letter speed code (L/M/S, or C<ms> for custom), joined with hyphens — e.g. a HELP/SAFE/42 sequence might suggest help-safe-42l. Rename the download however you like; it has no effect on the file's contents.
  • Case is never folded in that naming — "Hi" and "HI" are treated as different words, since they can look different on the actual display.
